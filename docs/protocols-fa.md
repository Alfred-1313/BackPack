# پروتکل‌ها و فوروارد در BackPack

<div dir="rtl">

اگر بخواهی کسی با اتصال به پورت ۸۰۸۰ روی شاتل به یک وب‌سرور روی پورت ۳۰۰۰ در فنلاند برسد، **فوروارد پورت** کافی است. اگر بخواهی دو ماشین آدرس خصوصی داشته باشند و چند برنامه یا یک زیرشبکه از همان مسیر استفاده کنند، به **تانل IP و مسیر شبکه** نیاز داری. نوع ترافیک برنامه و پروتکلی که آن را بین دو سرور حمل می‌کند دو انتخاب جدا هستند. مثلاً ممکن است برنامه TCP باشد و تانل بین دو سرور از QUIC روی UDP استفاده کند.

## گزینه‌های منوی OmniTunnel

| گزینه | چیزی که در این فورک جابه‌جا می‌کند |
|---|---|
| ICMP | بسته‌های IP داخل ICMP. این حالت به‌خودی‌خود رمزنگاری ندارد. |
| Routed UDP | بستهٔ IP از طریق UDP رمز‌شده؛ دو سمت رابط شبکه دارند. |
| Routed TCP | بستهٔ IP داخل یک جریان TCP رمز‌شده. |
| Routed TCP Mux | بسته‌های IP روی چند اتصال TCP؛ با Reverse Mux فرق دارد. |
| Routed WebSocket | بستهٔ IP روی WebSocket رمز‌شدهٔ این ماژول. |
| Hysteria2 | فوروارد پورت TCP و UDP روی QUIC با TLS. فوروارد TCP از رلهٔ محلی SOCKS5 می‌گذرد؛ فوروارد UDP را خود موتور انجام می‌دهد. |
| FoU | در این پیاده‌سازی، بستهٔ GRE داخل UDP قرار می‌گیرد. خروجی یک لینک IP است. |
| VXLAN | فریم Ethernet روی UDP؛ از بین این گزینه‌ها در لایهٔ ۲ کار می‌کند. |
| Reverse Mux | چند **فوروارد TCP** روی یک اتصال مشترک. لایهٔ زیرین از ICMP و بخش فوروارد از Chisel استفاده می‌کند. |
| Stripe | بسته‌های IP بین چند اتصال TCP تقسیم می‌شوند. |
| Ackless | بسته‌های IP با حامل TCP خام و فریم‌های احراز هویت‌شده جابه‌جا می‌شوند. |

وجود یک رابط شبکه به‌تنهایی تمام اینترنت ماشین را وارد تانل نمی‌کند. مسیرهای سیستم‌عامل مشخص می‌کنند کدام مقصد از آن رابط عبور کند. [مرجع OmniTunnel](omnitunnel.md)

## موتورهای اصلی BackPack

| خانواده | حالت‌های فورک | کاربرد |
|---|---|---|
| Reverse بر پایهٔ TCP | TCP، TCP Mux، TCP + Stealth، TCP + PCK | ورودی پورت‌های مشخص. Mux چند جریان را روی اتصال مشترک می‌برد. Stealth از لایهٔ رمزنگاری و PCK از حامل مبتنی بر بسته‌های TCP استفاده می‌کند. |
| Reverse بر پایهٔ UDP | UDP، KCP + FEC، QUIC | حالت سادهٔ UDP فقط دیتاگرام UDP حمل می‌کند. KCP و QUIC می‌توانند جریان قابل‌اعتماد را روی UDP حمل کنند. FEC اطلاعات اضافه‌ای برای جبران بخشی از بسته‌های گم‌شده می‌فرستد. |
| Reverse بر پایهٔ WebSocket | WS، WS Mux، WSS، WSS Mux | برای فوروارد پورت. WSS لایهٔ TLS اضافه می‌کند. Mux اجازه می‌دهد چند جریان از یک اتصال استفاده کنند. |
| Reverse روی ICMP | xDi | حامل ICMP برای فورواردهای موتور Reverse. با حالت Direct xDi که رابط IP می‌سازد متفاوت است. |
| حمل موتور Reverse با ابزار کمکی | Naive / HTTP2، XHTTP / TLS، REALITY / Vision، GOST v3 Relay / TLS | این گزینه‌ها اتصال موتور TCP را حمل می‌کنند. پیاده‌سازی این فورک در این حالت‌ها فوروارد TCP با یک مقصد اتصال تانل را پشتیبانی می‌کند. |
| Direct | GRE، IP6GRE، xDi، SNI، Spoof | برای اتصال شبکه‌ای. GRE و IP6GRE از هستهٔ لینوکس استفاده می‌کنند و به‌تنهایی رمزنگاری ندارند. xDi، SNI و Spoof حامل‌های متفاوت موتور Direct هستند. |
| Direct PCK | PCK | استثنای منوی Direct؛ موتور paqet پورت‌ها را فوروارد می‌کند و رابط IP کامل نمی‌سازد. |

**Reverse** مشخص می‌کند کدام سمت اتصال تانل را شروع می‌کند. در الگوی رایج این پروژه، فنلاند به شاتل وصل می‌شود و کاربر به پورتِ روی شاتل درخواست می‌فرستد. **SOCKS5 / HTTP Proxy** هم یک سرویس است که می‌شود به آن فوروارد کرد. [حامل‌های اصلی](transports.md) · [تانل Direct](l3-direct-tunnel.md) · [Direct PCK](direct-pck.md) · [نگاشت پورت](port-mappings.md)

فهرست بالا مربوط به فورک نسخهٔ ۲ است. وجود گزینه در کد با نصب بودن helper، امکان ساخت رابط در هستهٔ لینوکس و عبور ترافیک از شبکهٔ یک دیتاسنتر فرق دارد.

## خلاصهٔ فارسی

فوروارد پورت ورودی یک سرویس را به مقصد مشخص می‌رساند. تانل شبکه رابط خصوصی می‌سازد و مسیرهای سیستم‌عامل تعیین می‌کنند کدام ترافیک از آن بگذرد. Hysteria2 و Reverse Mux در این فورک برای فوروارد پورت به کار می‌روند. پشتیبانی کد، نصب ابزار کمکی و عبور پروتکل از شبکهٔ دیتاسنتر را هنگام راه‌اندازی بررسی کن.
